A retrieval system can fail in two ways only

What must a retrieval system do?

A person has an information need and types a query. The system gives a ranked list. The person reads the list from the top and stops at some point. The system must put the relevant documents above that point.

Failure 1: a finding failure

The relevant document is not in the list. No change to the order can correct this failure. Recall measures this failure.

Failure 2: an ordering failure

The relevant document is in the list, but at a low rank. The user stops before the document. MRR, DCG, and nDCG measure this failure.

Each metric contains one simulated user (see the table of terms above). The rules of the simulated user tell you three things: where the user stops, what the user wants, and which failure the metric can see. All metrics on this page come from this idea.

Note: A metric can only see documents that a person judged. The set of judgments has the name qrels. A metric counts an unjudged document as not relevant.

This undoes piece 2 for the full set of queries. It changes the score back into a distance. In plain English: a typical number of documents that the user reads to get to the first useful one. The name of this number is the harmonic mean rank.

How the pieces come together. For each query, find how much of the reading up to the first useful document was useful (pieces 1 and 2). Then take the value of a typical query (pieces 3 to 5). To say the result as a distance, divide 1 by it (piece 6).

Why 1 ÷ rank, and not the rank itself?

There are three reasons. First, a rank has no upper limit, and a query with no relevant document has no rank. The value 1 ÷ rank puts all queries on one scale from 0 to 1, and “not found” becomes 0. Second, a larger value is better, as for all other metrics on this page. Third, the reciprocal gives most weight to the top ranks: 11 − 12 = 0.50, but 15 − 16 = 0.03. This is correct for a user who cares most about the first results.

Why is 1.76 not the normal mean rank? The normal mean of the ranks is 1 + 2 + 53 = 2.67. The harmonic mean rank is 10.567 = 1.76. It is smaller because piece 2 gives most weight to the top ranks. Thus, MRR is sensitive to the first few ranks and almost ignores changes lower in the list.

How to read a value. MRR = 0.40 gives 10.40 = 2.5. Thus, the first relevant document is typically near rank 2 or 3. Caution: one MRR can come from very different results. For example, if half of the queries have the first relevant document at rank 1 and the other half have none, MRR is 1 + 02 = 0.50. Look at the RR values for each query before you make a decision.

Why log2(i + 1)?

log2(x) is the power of 2 that gives x. For example, log2(8) = 3, because 2 × 2 × 2 = 8. Thus, the divisor increases by 1 only when i + 1 doubles. The attention decreases fast at the first ranks and slowly after them.

The “+ 1” gives rank 1 the value log2(2) = 1. Thus, rank 1 has no discount.

Piece 7
The limit of DCG: there is no fixed maximum

The maximum DCG depends on the query: how many relevant documents it has, and their grades. Thus, a DCG value alone cannot tell you if a result is good or bad. nDCG, in the next section, solves this problem.

One grade-3 document: maximum DCG@10 = 3.0  ·  Ten grade-3 documents: maximum DCG@10 = 13.6
How the pieces come together. The name has three ideas, and each idea adds one step. G: give each document a value from its grade (piece 1). C: add the values (piece 2). D: before you add, make the value smaller at lower ranks, because the user gives them less attention (pieces 3 to 5). The result is DCG@k: the total value that the user gets from the top k, with more weight at the top (piece 6). It has no fixed maximum (piece 7).

The discount curve is the attention of the user. At rank 1 the attention is 1. At rank 10 it is 0.29. With 1/rank (the MRR user), it is only 0.10 at rank 10. Thus, the DCG user reads a full page. The MRR user stops early.

Why is there no good DCG value? Query A has one relevant document of grade 3. Its maximum DCG@10 is 3. Query B has ten relevant documents of grade 3. Its maximum DCG@10 is 13.6. A DCG of 5 is not possible for query A, and it is a poor value for query B. Thus, a DCG value alone has no meaning. Always use nDCG.

Piece 5
Where did the missing value go?

nDCG loses value for two causes. Order loss: the relevant documents are in your top k, but in a wrong order. A better reranker can fix this. Finding loss: some relevant documents are not in your top k. A better retriever can fix this.

To separate the two, put your own top k in the best order, and calculate nDCG again.

Your list in the best order (3, 2, 0): DCG = 4.26, nDCG = 0.895. Order loss = 0.895 − 0.840 = 0.055. Finding loss = 1 − 0.895 = 0.105, from the missed grade-1 document.

How the pieces come together. DCG alone has no scale (piece 1). Build the best possible list for the same query (piece 2) and calculate its DCG (piece 3). The ideal list contains all relevant documents in the qrels, in decreasing grade order. It includes the missed documents. Thus, nDCG sees both failures: a wrong order, and relevant documents that are not in the top k.

How the metrics fit a two-stage system

Many retrieval systems have two stages: a retriever that finds candidates, and a reranker that sets their order. A common report uses one metric for each hand-off: Recall@k for the candidates, nDCG@k for the final order, and Success@k for what a user or an LLM sees. The diagram uses k = 40, 10, and 5 as examples. Use the values of k that fit your system.

Relations that are always true

Success@5 ≤ Success@10, because a larger k can only add documents. Recall@k ≤ Success@k for each query, because recall is more than 0 only when success is 1. Recall@10 ≤ Recall@40. If your results do not obey these relations, examine your evaluation code.

Section 5 of 6

What is a good value?

Is nDCG@10 = 0.45 good or bad?

There is no universal good value. A number has a meaning only when you compare it with three references: a floor, a ceiling, and the difficulty of the dataset.

The floor

A simple baseline on the same queries and qrels. BM25 is the usual floor. If your system is not better than BM25, it is not good, at any value.

The ceiling

The best possible value. For nDCG this is 1 in theory. For a reranker, the ceiling is the value of a perfect order of the candidates that the retriever gave.

The dataset has more effect than the system

The chart shows nDCG@10 for two systems on 14 BEIR datasets. BM25 gets 0.149 on SCIDOCS and 0.789 on Quora. The system is the same. Only the dataset changes. Thus, 0.40 can be a good value on one dataset and a bad value on another dataset.

Data: BM25 and SPLADE-v3 results from “A Systematic Multi-Domain Evaluation of Document Retrievers” (arXiv 2609.29455). Note that SPLADE-v3 is better on 13 datasets, but worse on Touché-2020.

The procedure to judge a value

  1. Run BM25 on the same corpus, queries, and qrels. Record the same metrics that you report for your system. This is the floor.
  2. Calculate the ceiling of your reranker. Put the relevant documents of the candidates (for example, the top 40) in the ideal order. Then calculate nDCG@10 for this list.
  3. Calculate the fraction of the gap that your system closes: (system − floor) ÷ (ceiling − floor).
  4. Find the queries with Success@10 = 0. Read 20 of these queries and their results. Find the cause of each failure.
  5. Use the cost of a failure to make a decision. For RAG with 5 passages, 1 − Success@5 is the fraction of answers with no relevant context.
  6. Make sure that a difference between two systems is real. Use a paired test on the values for each query, for example a paired t-test or a bootstrap. A small set of queries gives a large noise.

0.25 ÷ 0.50 = 0.50: your system closes half of the gap
How the pieces come together. Measure your improvement over the floor (piece 1) and the room that exists (piece 2). Their ratio (piece 3) is easier to compare across datasets than the raw value, because it removes the effect of an easy or a difficult dataset.
