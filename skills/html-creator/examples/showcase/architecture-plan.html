Architecture plan · AP-7 · Replaces ADR-3

Episode-to-chapters planning service

One pinned episode enters the system. One verified plan or one typed stop result leaves it. This plan specifies the four stages, their contracts, the terminal states, and the gate that decides between them.

Authority. This plan replaces ADR-3 and the stage sketches in PLAN-5. The episode schema v2 and the citation format remain authoritative. Rendering, playback, and packaging are outside its scope.

Overview

Four stages, one gate

The service compiles a chapter plan from a pinned episode. Each stage has one input contract, one output contract, and one failure mode it must report.

0 · Scope

Pin the input, compile policy, set budgets for duration, beats, and chapters.

Output: scoped request

1 · Evidence

Build the cited scene view. Every claim in the plan points at a source span.

Output: evidence view

2 · Reason

Prove the beats and solve chapters against the budgets. Repair is bounded to two passes.

Output: candidate sequence

3 · Verify

Fit the output and apply the hard gates. A failure emits a typed stop, never a partial plan.

Output: plan or typed stop
Invariant. A stage never returns to a closed stage. Repair moves one step back at most, and at most twice per run.
Glossary

Terms used in this plan

One term per concept. The same word keeps the same meaning in code, diagrams, and tests.

Episode
The source material: a transcript, a chapter list, or a story bible.
Pinned input
An episode with a content hash. The hash anchors every citation.
Beat
A story event that the plan must place. Beats are proven before chapters are solved.
Chapter
A timed segment of the output. Chapters carry beats and citations.
Evidence view
The set of source spans the plan may cite, with offsets into the pinned input.
Hard gate
A check that emits a typed stop on failure. Soft gates only record a warning.
Typed stop
A terminal result that names the blocking reason. It carries no partial plan.
Bounded repair
A return from stage 3 to stage 2. Maximum two passes, then a typed stop.

States

Failure and result states

Every run ends in exactly one state. A typed stop names the blocker; it never carries a partial plan.

StateBadgeMeaningNext action
VERIFIED_PLANverifiedAll hard gates passed. The plan is complete and cited.Ship to rendering.
TYPED_STOP_INVALIDstopThe input could not be pinned or parsed.Fix the source, resubmit.
TYPED_STOP_UNSOLVEDstopBounded repair exhausted. Beats remain unproven or budgets unfit.Relax budgets or extend evidence.
PARTIAL (rejected)invalidAny result that carries a plan with a failed hard gate.Never emit. Treat as a verifier bug.
Tests

Stage verification gate

The method stays visible next to the cases. Good and bad output are stated per stage.

Method

Replay one pinned input per stage. Change one field at a time and record the emitted state.

Good output

References resolve, every hard gate record is present, and the state is terminal and typed.

Bad output

A partial plan, a missing gate record, or an untyped failure. All three fail the run.

Minimum scope

One positive case and one typed negative case per stage gate before merge.

CaseInput changeExpected state
T1 · valid episodeNone. Pinned transcript.VERIFIED_PLAN, three gate records, no warnings.
T2 · unpinnable sourceCorrupt hash.TYPED_STOP_INVALID, emitted at stage 0.
T3 · missing citationDrop one span from the evidence view.Repair pass, then TYPED_STOP_UNSOLVED.
T4 · budget overflowDuration budget below the solved minimum.Repair pass, then TYPED_STOP_UNSOLVED.
T5 · gate record missingVerifier stub omits budgets_fit.Invalid runResult. Verifier bug, blocked at review.
T6 · third repair passForce a third failure after two passes.TYPED_STOP_UNSOLVED. The loop must not run again.
